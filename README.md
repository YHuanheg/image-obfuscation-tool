# 图片混淆工具 · 小番茄 &amp; 光棱坦克

一个**单文件、零依赖、完全离线**的网页工具，支持两种网上流传最广的图片处理玩法：

- **小番茄图片混淆** —— 把一张图彻底打散成看不出内容的样子，用相同密钥可以**无损还原**；
- **光棱坦克图片工厂** —— 把两张图合成一张「伪隐写图」：正常看是表图，调整亮度阈值后显出里图。

打开 `小番茄与光棱坦克图片混淆工具.html` 即可使用。所有计算都在你自己的浏览器里完成，**图片不会上传到任何服务器**。

---

## 一、直接使用

1. 下载 `小番茄与光棱坦克图片混淆工具.html`（单个文件，约 78 KB）；
2. 双击用任意现代浏览器打开（Chrome / Edge / Firefox / Safari 均可）；
3. 把图片拖进页面即可，无需安装、无需联网。

工具内自带「原理说明」标签页，写清楚了每个算法的数学原理与参数含义。

## 二、功能

工具分为四个标签页。

### 1. 小番茄图片混淆

- 批量上传，一键**混淆**或**解混淆**；
- **可手动指定处理次数**（1 ~ 1,000,000 次）：连续混淆 n 次 ≡ 沿曲线一次位移 `(n × O) mod N`，因此工具只跑一趟搬运，次数填多大都是瞬间完成，结果与手动点 n 次**逐像素完全相同**；
- 每张结果卡片会标出该尺寸的 `N / O / 可见周期 m / 等效偏移`，并在「这次操作等于什么都没做」时给出警告；
- 密钥（偏移系数）可调，`1.000` 即原始小番茄工具的默认行为；
- 输出格式可选 **PNG（默认，推荐）** 或 JPEG；
- 超过 1 张时自动打包成 ZIP 下载（内置极简 ZIP 写入器，无第三方依赖）。

> **关于「可见周期 m」**：位移在 `Z_N` 中生成的循环子群阶为 `m = N / gcd(O, N)`。
> 于是「混淆 n 次」与「混淆 n + m 次」输出**完全相同**，混淆 `m` 次则**等于什么都没做**。
> 也就是说，「这张图被混淆了几次」这个问题**只能确定到模 m**，并不存在唯一答案 ——
> m 因尺寸而异：80×45 只有 144，100×100 是 500，1920×1080 是 15360，而 2160×3840 是 8,294,400（几乎不重复）。

> **密钥必须一致才能还原**，密钥错了只会得到一张噪声图。

### 2. 光棱坦克图片工厂

**制作（编码）**：分别上传「里图（要藏起来的）」和「表图（正常看到的）」，实时预览合成结果，并提供**显形测试**面板即时验证效果。

可调参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 里图阈值 Ti | 24 | 里图被压缩到的暗部上限，即 `[0, Ti]` |
| 表图阈值 Tc | 42 | 表图被压缩到的亮部下限，即 `[Tc, 255]` |
| 里图/表图 转灰度 | 里图关、表图开 | 转灰度能让亮度区间更好控制 |
| 里图/表图 对比度 | 0 | 范围 −255 ~ 255，逐像素线性拉伸 |
| 交错方向 | 行优先 | 行优先 = 对角棋盘（推荐） |
| 斜率 slope | 1 | 与 gap 共同决定交错纹路 |
| 间隔 gap | 1 | `gap=1, slope=1` 即 `(x+y) mod 2 == 0` |
| 最大边长 maxSize | 1200 | 超过则等比缩小；里图按此限制，表图自动中心裁剪对齐 |
| 反色 | 关 | 交换明暗区，里图进亮部、表图进暗部 |

**显形（解码）**：载入混淆图后拖动阈值滑杆**实时**显形，支持 6 种遮罩填充方式。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 下 / 上阈值 | 0 / 24 | 命中该亮度区间的像素会被拉伸到满量程显示 |
| 遮罩填充 | ltavg | 未命中像素的处理方式，见下 |
| 对比度 | 0 | 显形后再做一次对比度拉伸 |

填充方式：`black` 纯黑、`white` 纯白、`transparent` 透明、`lcopy` 复制左邻、`tcopy` 复制上邻、`ltavg` 取左/上/左上的均值（推荐，能把棋盘纹路抹成平滑背景）。

**调参口诀**：阈值区间选中哪一段亮度，就显示哪一张图。

- 看**里图** → `0 ~ Ti`（默认 `0 ~ 24`）
- 看**表图** → `Tc ~ 255`（默认 `42 ~ 255`）

### 3. 更多混淆算法

移植自开源库 [ObfuscationUtils](https://github.com/2195517546/ObfuscationUtils)（MIT）：

| 算法 | 密钥类型 | 尺寸变化 | 特点 |
| --- | --- | --- | --- |
| PicEncrypt 行混淆 | 0~1 浮点 | 不变 | Logistic 混沌映射，按列置换 |
| PicEncrypt 行列混淆 | 0~1 浮点 | 不变 | 行列各置换一次，打散更彻底 |
| 方块混淆 Block | 任意字符串 | 可能变大 | 32×32 块置乱，补边到 32 的倍数 |
| 行像素混淆 RowPixel | 任意字符串 | 不变 | MD5 置乱，行内打乱像素列 |
| 逐像素混淆 PerPixel | 任意字符串 | 不变 | MD5 置乱，行列双向置换 |

## 三、算法原理速览

### 小番茄：希尔伯特曲线 + 黄金分割循环位移

本质是**像素索引的循环置换**，不是密码学加密。

```text
φ' = (√5 − 1) / 2 ≈ 0.6180339887
offset = round( φ' × W × H × key )  mod  (W × H)

混淆：  out[ curve[(i + offset) mod N] ] = src[ curve[i] ]
解混淆：out[ curve[i] ]                  = src[ curve[(i + offset) mod N] ]
```

`curve[]` 是 `gilbert2d(W, H)` 递归生成的**希尔伯特空间填充曲线**索引序列：它走遍每个像素且不重复，并且**空间上相邻的点在序列里也相邻**。因为位移是「沿曲线」而不是「按行」，曲线的二维跳变把**整体构图**彻底打乱 —— 一块连贯的色块会被搬到画布的另一头，所以看内容完全认不出。

但要注意：它打乱的是**全局位置**，不是**局部平滑度**。曲线的空间局部性意味着「图上相邻」的两个像素在曲线序列里也往往只差一百多步（256×256 实测平均差 **156** 步，而随机取两像素期望差 **21845** 步）；而循环位移不改变曲线上的邻接关系，因此混淆图的相邻像素平均色差仍只有随机置换的约 **4%**（实测 6.99 vs 182.11）。这正是官方所宣称的「保持空间相关性、压缩后仍能还原」的真实机制。

代价是**安全性很弱**：密钥只是一个标量，已知算法即可暴力枚举。

### 光棱坦克：灰度值分离 + 像素交错

```text
归属判定（默认 slope=1, gap=1, 行优先）：
    isCover(x, y)  ⇔  (x + y) mod 2 == 0        ← 对角棋盘，一半给表图，一半给里图

亮度压缩：
    里图：  inner'(v) = floor( v × Ti / 255 )              ∈ [0, Ti]
    表图：  cover'(v) = floor( Tc + v × (255 − Tc) / 255 ) ∈ [Tc, 255]

解码：
    l = 0.299R + 0.587G + 0.114B
    l ∈ [lo, hi] →  v' = clamp( (v − lo) × 255 / (hi − lo) )
    否则          →  用遮罩填充方式处理
```

默认 `Ti = 24`、`Tc = 42`，于是输出图里**里图像素亮度必在 `[0,24]`、表图像素亮度必在 `[42,255]`，两个区间零重叠** —— 这就是解码时能把它们干净分开的根本原因。

**为什么正常看是表图**：人眼在正常距离下会做空间平均，棋盘上一半暗（里图）一半亮（表图），平均后亮度被高亮的表图主导，里图被「淹没」在平均过程里。

## 五、已知限制

这些限制大多来自上游实现或浏览器本身，工具里也都如实标注了，**没有偷偷「修好」**（改了就无法与上游产物互通）。

| 限制 | 原因 | 影响 |
| --- | --- | --- |
| **JPEG 输出不是无损的** | 像素值本身没被改动，但 JPEG 的 DCT 量化会改值；改多少取决于图的细节密度 | 实测 256×256：照片类图「混淆→JPEG(q0.95)→解混淆」平均像素误差约 **1.18/255**（肉眼几乎无感），细节极密的图可达 **32/255**；**PNG 为 0（逐像素无损）**。反复保存会累积。除非要对接旧工具产物，否则请保持 PNG |
| **缩放 / 裁剪 / 旋转后无法还原** | 曲线遍历顺序与偏移量 `O = round(0.6180339887 × 宽×高)` **都只由宽高决定**；宽高一变，逆置换就作用在错误的序列上 | 彻底失败（输出必为乱码），不是「画质下降」而是「对不上」。**压缩（JPEG/WebP，同尺寸）不影响可还原性，改尺寸则一定失败** |
| **方块混淆对非 32 倍数的尺寸无法完全还原** | 上游实现会补边到 32 的倍数，加密与解密使用不同的宽高取模 | 与上游行为一致；要求无损请先把图片裁成 32 的倍数 |
| **半透明像素往返有 ±2 精度损失** | 浏览器 canvas 对 alpha 做预乘，`putImageData → toBlob → drawImage → getImageData` 不是逐字节恒等 | 仅影响含半透明区域的 PNG；**不透明图片完全不受影响** |
| **小番茄安全性弱** | 密钥只是单个标量 | 已知算法即可枚举密钥，属于「混淆」而非「加密」 |
| **光棱坦克怕二次压缩** | 逐像素棋盘结构 + 依赖亮度区间 | 社交平台会二次压缩并可能丢失元数据，发送时务必勾选「原图」 |
| **大图处理会卡顿** | 逐像素循环在主线程执行 | 建议单边控制在 4096 以内；界面会在每张图之间让出主线程，但单张大图仍会短暂阻塞 |
