小番茄图片混淆

基于希尔伯特（Hilbert）空间填充曲线重排全部像素，并沿曲线做一次 黄金分割循环位移。整图被彻底打散，肉眼无法辨认；用相同密钥反向操作即可无损还原。

点击选择 或把图片拖到这里
支持多张 · PNG / JPG / WEBP / GIF / BMP
密钥必须一致才能还原。密钥 1.000 等价于原始小番茄工具的默认偏移 round(0.618 × W × H)；输入 0.618 可得 round(0.618² × W × H)。

关于透明图：浏览器 canvas 对半透明像素会做 alpha 预乘，含半透明区域的图片往返会有 ±2 左右的精度损失；不透明图片（绝大多数照片、截图）不受影响，完全无损。

一、小番茄图片混淆

本质是一个 像素索引的循环置换，不含加密密钥的密码学强度，属于「混淆」而非「加密」。

1. 希尔伯特曲线把二维图像拉成一维

gilbert2d(W, H) 递归生成一条空间填充曲线：它走遍每一个像素点且不重复，并且 空间上相邻的点在序列中也相邻。得到一个索引数组 curve[]，长度为 N = W × H，其中 curve[i] 表示曲线的第 i 步落在哪个像素上。

2. 黄金分割偏移 + 整条曲线的循环位移

// φ' = (√5 − 1) / 2 ≈ 0.6180339887
offset = round( φ' × W × H × key )

// 混淆：把曲线上第 i 个像素搬到第 (i + offset) 个位置
out[ curve[(i + offset) mod N] ] = src[ curve[i] ]

// 解混淆：反过来搬
out[ curve[i] ] = src[ curve[(i + offset) mod N] ]

因为「沿曲线位移」而不是「按行位移」，曲线在二维上的跳变把**整体构图**彻底打乱 —— 一块连贯的色块会被搬到画布的另一头，所以看内容完全认不出。但要注意：它打乱的是 全局位置，不是局部平滑度。曲线的空间局部性意味着「图上相邻」的像素在曲线序列里也往往 只差一百多步（随机两像素则差上万步），而位移不改变曲线上的邻接关系，所以混淆图的相邻像素差 仍只有随机置换的约 4% —— 这正是官方宣称「保持空间相关性、压缩后仍能还原」的真实机制。同时它完全可逆且不丢像素（前提是输出用无损格式）。

项目说明
曲线生成递归分形，按宽高比 2w > 3h 切换切分策略，w==1 或 h==1 时线性收尾
偏移量round(0.6180339887 × N × key)，再对 N 取模
时间复杂度O(N)，N 为像素总数
可逆性是（同一密钥取逆置换）——但仅限宽高不变的图；缩放 / 裁剪 / 旋转会同时改变曲线顺序与偏移量，逆置换立刻失效，必然还原成乱码
安全性弱：密钥只是一个标量，已知算法可暴力枚举

3. 连续混淆 n 次，会发生什么（本工具的「处理次数」就是干这个）

每次混淆都是「沿同一条曲线位移 O」，而位移是可以叠加的，于是： 

// n 次混淆 == 曲线空间的一次位移 n·O
E^n(img)  ≡  shift(img, (n × O) mod N)          // 逐像素完全等价，不需要真的循环 n 遍

// 位移在 Z_N 中生成的循环子群，阶（也就是「可见周期」）为：
m = N / gcd(O, N)

∴  混淆 n 次 与 混淆 n + m 次，输出完全相同
∴  混淆 m 次 == 什么都没做（结果与原图逐像素一致）

这两个推论有两个很实际的后果：①「这张图被混淆了几次」在数学上无法确定 —— 只能确定到模 m，混淆 3 次和混淆 503 次（100×100 时 m=500）产出的文件一模一样， 任何算法都区分不了，不是方法不够聪明，而是信息根本不存在； ② m 可以很小 —— 80×45 只有 144，也就是那张图最多只有 144 种不同外观。 本工具会在每张结果卡片上标出它的 N / O / m / 等效偏移， 并提示「这次操作是否等于什么都没做」。

尺寸NO可见周期 m含义

格式坑：原始工具输出固定为 JPEG（质量 0.95）。实测「混淆→JPEG→解混淆」对照片类图 平均误差只有 1.18/255（几乎无感），但细节极密的图可达 32/255。 本工具默认输出 PNG，做到逐像素无损（实测误差 0）； 若必须与旧工具互通，再切到 JPEG 选项。
只在同尺寸下可还原。曲线遍历顺序与偏移量 O 都只由宽 × 高决定： 同尺寸重新编码（JPEG/WebP 压缩）不影响可还原性； 但一旦缩放 / 裁剪 / 旋转，宽高变了，曲线与 O 同时改变， 逆置换就作用在错误的序列上 —— 必然还原成乱码，不是「画质差一点」。

二、光棱坦克（Mirage / Prism）

基于 灰度值分离 + 像素交错 的伪隐写：一张图承载两张图，靠人眼/显示阈值的差异切换。

1. 按棋盘格决定每个像素归谁

isCover(x, y):
  slope == 0        →  (isRow ? y : x) mod (gap + 1) < gap
  isRow  (行优先)   →  (y / slope + x) mod (gap + 1) < gap
  !isRow (列优先)   →  (x / slope + y) mod (gap + 1) < gap

默认 slope=1, gap=1, 行优先，即 (x + y) mod 2 == 0 的对角棋盘：一半像素给表图，一半给里图。

2. 把两张图的亮度压进互不重叠的区间

// 里图 → 低亮度区间 [0, Ti]
inner'(v) = floor( v × Ti / 255 )

// 表图 → 高亮度区间 [Tc, 255]
cover'(v) = floor( Tc + v × (255 − Tc) / 255 )

// 反色模式则把两式对调：inner'(v) = 255 − Ti + v·Ti/255, cover'(v) = v·(255 − Tc)/255

默认 Ti = 24、Tc = 42。于是输出图里： 里图像素亮度必在 [0,24]，表图像素亮度必在 [42,255] —— 两个区间零重叠， 这就是解码时能把它们干净分开的根本原因。

3. 为什么「正常看是表图」

人眼在正常距离下会对相邻像素做空间平均。棋盘上一半是暗的里图像素、一半是亮的表图像素， 平均后亮度约为 (inner' + cover') / 2，主要被高亮的表图主导， 因此第一眼看到的是表图（略暗），里图被「淹没」在平均过程里。

4. 解码：用亮度阈值把两张图拆开

l = 0.299 R + 0.587 G + 0.114 B          // 感知亮度（Luma）

if (l >= lowerThreshold && l <= higherThreshold)
      v' = clamp( (v − lower) × 255 / (higher − lower) )   // 命中区间 → 拉伸到满量程
else
      用邻域填充（black / white / transparent / lcopy / tcopy / ltavg）
想看的图阈值区间原因
里图0 ~ Ti（如 0 ~ 24）里图像素全在暗部，被拉伸到 0~255 后清晰可见
表图Tc ~ 255（如 42 ~ 255）表图像素全在亮部；暗部的里图像素被邻域填充抹平

阈值必须对准生成时用的 Ti / Tc：区间取错（例如用 25 ~ 255 而非 42 ~ 255） 不会看错图，但会引入固定的亮度偏移与对比度压缩，画面发灰。

ltavg 会从左、上、左上三个已处理过的邻居取平均来填补未命中区域， 一次从左到右、从上到下的扫描即可把整片棋盘纹路抹成平滑背景，是默认且效果最好的填充方式。

传输坑：JPEG 的色度二次采样会破坏逐像素的棋盘结构（灰度图受影响小，彩色图会明显串色）； 社交平台还会二次压缩并可能丢失 PNG 的 tEXt 元数据。因此本工具默认输出 PNG， 发送时务必勾选「原图」。

三、更多混淆算法

PicEncrypt 系列 · Logistic 混沌映射

x₀ = key                      // 必须是 (0, 1) 之间的浮点数
xₙ₊₁ = 3.9999999 × xₙ × (1 − xₙ)

// 把 [值, 下标] 按值升序排序，取下标序列就是置换表 positions[]
positions = argsort( [x₀, x₁, ..., xₙ₋₁] )
  • 行混淆：按 positions 置换列（整列搬运，尺寸不变）
  • 行列混淆：逐行推进混沌序列 x 做行内置换，再逐列推进做列内置换；解密时顺序颠倒（先列后行）

混沌系统对初值极度敏感，密钥差 1e-9 就会得到完全不同的置换表 —— 比小番茄的单一标量偏移更难猜测。

MD5 密钥置乱系列

// Fisher–Yates 洗牌，牌面随机数来自 MD5(key + i)
for i = len−1 → 1:
    rand = parseInt( MD5(key + i).hex[0..6], 16 ) mod (i + 1)
    swap(arr[rand], arr[i])
  • Block 方块混淆：把图补边到 32 的倍数后切成 32×32 块，用两套洗牌表分别置换块的行、列坐标（输出尺寸可能变大）
  • RowPixel 行像素：按 xArray[(xArray[j % W] + i) % W] 在行内打乱像素列
  • PerPixel 逐像素：在行、列两个方向同时置换，打散最彻底

四种方式对比

算法密钥尺寸变化混淆强度速度
